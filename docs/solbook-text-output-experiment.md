## 텍스트 규칙

`app/solbook_text_renderer.js`는 기준 쏠북메이커의 유형 별칭과 마커/선지 정리 함수를 가져온 읽기 전용 출력 어댑터입니다.

- 발문, 본문, 선지를 분리합니다. PDF LAB의 A/B/C 선지 표 대신 쏠북 형식의 번호 목록을 사용합니다.
- 순서는 (A)/(B)/(C) 문단으로 구분하고, 삽입문과 요약문은 본문과 빈 줄로 분리합니다.
- `[[blank]]`, `[[blank:A]]`, `[[u:...]]`, `[[box:A:left|right]]`, `[[s]]`/`[[slot]]`를 해석합니다.
- 밑줄어법/밑줄어휘는 밑줄 앞에 ①~⑤를 붙이고 기존 번호와 중복되지 않도록 합니다.
- 순서 선지의 구분 기호는 줄바꿈 방지 공백과 ASCII 하이픈을 사용합니다.
- 일반 선지에 있는 의미 있는 `/` 또는 `(A)`는 무조건 제거하지 않습니다. 분절 정리는 요약/순서/선택어법/선택어휘/연결사에 한정합니다.
- 쏠북의 Noto Sans KR 폰트, 발문 10.5pt, 본문·선지 9.5pt, 줄간격 1.5를 사용합니다. 문제지 전체 제목과 여백 설정은 PDF LAB 설정을 유지합니다.
- 긴 선택 박스는 카드 폭 안에서 줄바꿈할 수 있습니다. 쏠북 jsPDF와 브라우저 PDF의 폰트 굵기·줄바꿈이 픽셀 단위로 같음을 보장하지는 않습니다.

저장된 텍스트를 출력할 뿐 OCR 오타를 고치거나 원본 이미지에서 누락된 밑줄을 추측하지 않습니다. 원본 문항/정답/해설 데이터는 수정하지 않습니다.

## 페이지 배치와 성능

- 텍스트 출제에서는 이미지 blob/Storage URL 다운로드를 건너뜁니다.
- 폰트 준비 후 실제 카드 높이를 측정해 배치합니다. 결과는 최대 512개 캐시에 재사용합니다.
- 한 문항이 한 단 높이를 넘으면 잘린 PDF를 내보내는 대신 문항 번호와 조정 안내를 표시합니다.
- 이미지 출제는 기존 높이 계산/압축 경로를 그대로 사용합니다.

```powershell
node tests/solbook_text_renderer.test.cjs

# Playwright가 일반 의존성에 없으면 설치된 런타임 node_modules 경로 지정
$env:PDFLAB_NODE_MODULES = 'C:\Users\CHOI\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules'
node tests/solbook_text_browser.cjs
```

브라우저 검사는 새 격리 프로필의 headless Edge에서 동작하며 외부 요청은 차단합니다. 사용자 브라우저나 실제 Firebase 데이터는 사용하지 않습니다.

- 대표 16유형: 양쪽 진입점 모두 16문항, A4 4페이지
- 모든 페이지의 PDF 렌더링을 눈으로 확인: 문항/선지 잘림 및 텍스트 넘침 없음
- 원시 마커 노출 없음, A/B/C 표 없음, 양쪽 진입점의 본문 동일
- 원본 데이터 비변경, 이미지 다운로드 미호출, 긴 문항 출력 차단 확인
- 쏠북 원본 정규화 함수와 마커/유형별 선지 출력 일치 검사
- 구형 `sequenceParts`, 템플릿 키 없는 삽입 자료, 서술형, 공통지문, HTML 이스케이프 검사
- 320문항 배치 계산 약 0.17~0.22초 (이 PC, 합성 데이터, 전체 PDF 저장 시간 아님)
- PDF 텍스트 재추출에서 1~16번 문항 번호가 모두 존재함을 확인

검증 산출물은 `tmp/pdfs/solbook-text-qa/`에 있으며 커밋 대상이 아닙니다. 실제 새 학기 문항으로 최종 사용자 확인 후 채택 여부를 결정하면 됩니다.
