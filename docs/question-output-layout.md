# 문제 출력 문구와 높이 기반 페이지 배치

기준 커밋: `e805a2b51819d095b1c62e5bd620ed62058e4a9b`.

세 화면의 `buildLayoutPages`는 `app/problem_page_layout.js`를 사용한다. 텍스트와 이미지 카드의 실제 렌더링 높이, 최소 카드 간격, 두 단, 기존 페이지·제본 여백과 머리말 공간으로 배정을 먼저 완료한다. 머리말도 실제 높이를 측정하여 첫 페이지 단의 사용 가능 높이에 반영한다. 질문 페이지에서는 저장된 `maxPerColumn` 값을 문항 수 상한으로 사용하지 않는다. 시험 전체 선택 문항 수 제한은 기존 슬롯/선택 경로에서 처리한다.

완성된 단에 독립적인 카드가 2개이면 `is-two-questions`로 첫 카드는 상단, 둘째 카드 하단은 단 하단에 맞춘다. 1개 또는 3개 이상이면 위에서부터 최소 간격으로 배치한다. 공통지문 연결, 같은 그룹의 자식, 같은 문항의 연속 조각은 간격을 늘리지 않는다. 카드에는 `flex: 0 0 auto`를 적용하며 두 문항을 넣기 위한 자동 압축은 하지 않는다. 기존 수동 이미지 압축 선택은 유지한다.

꼬리 묶음은 현재 페이지와 빈 다음 페이지의 두 단에 시험 배치한다. 다음 페이지에만 들어가면 전체를 이동한다. 한 단보다 긴 텍스트는 기존 문단·선지 분할기를 사용하되, 앞 단의 남은 공간부터 이어서 나눌 수 있다. 빈 페이지 두 단에도 들어가지 않을 때만 페이지를 나누고 `계속`을 표시한다. 이미지가 한 단보다 길면 폭을 유지한 연속 세로 구간으로 나누어 출력한다. 원본 이미지와 canonical 데이터는 수정하지 않는다.

공통지문 시작 안내는 `다음 글을 읽고 물음에 답하시오.` 한 번이며 이어지는 지문 조각에는 `지문 (계속)`을 사용한다. 중복 공통지문 배지와 내부 그룹 참조 줄은 생성하지 않는다. 원문 발문·본문에 있는 출전 문자열은 보존한다. 일부 자식만 선택하면 그 자식과 공통지문만 출력한다.

정답·해설 HTML 배치는 유지한다. 일반 출제의 별도 답지 이미지 배치는 기존 `buildAnswerLayoutPages` 경로를 유지한다. 미리보기와 최종 인쇄 HTML은 동일한 카드·페이지 생성 함수와 CSS를 사용한다.

## 격리 검증

기존 Playwright/Edge와 Python(pypdf, Poppler) 환경에서:

```text
node tests/run_question_layout_review.cjs
```

필요하면 `PDFLAB_NODE_MODULES`와 `PDFLAB_PYTHON`을 기존 설치 경로로 지정한다. 실제 P05 fixture는 로컬 전용이다. 운영 Firebase·사용자 DB·실사용 브라우저 프로필을 사용하지 않는다.

결과는 `tmp/question-layout-review/`에 저장된다. 기존 8개 호환성 검사, 세 화면의 전후 PDF 생성, 17개 배치 사례, 실제 PDF의 문항·정답 대응 및 Poppler 이미지가 포함된다. 기존 PDF 검사의 페이지 번호 상수는 문항/내용/정답 식별 검사로 대체했다. baseline은 Git의 기준 커밋 파일을 읽어 격리 브라우저에서 제공하므로 현재 작업 트리를 되돌리지 않는다.
