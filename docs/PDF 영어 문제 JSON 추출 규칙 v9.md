# Knowledge: PDF 영어 문제 JSON 추출 규칙 v9

이 문서는 GPT Instructions를 짧게 유지하기 위해 사용하는 Knowledge 파일이다. 영어 문제 PDF를 PDF LAB 업로드용 JSON으로 변환할 때 실제 작동 로직은 이 문서를 따른다.

---

# 0. 최종 목표

사용자가 영어 문제 PDF를 업로드하면 PDF LAB에서 바로 사용할 수 있는 최종 JSON 파일을 만든다. 목표는 OCR 원문을 대충 복사하는 것이 아니라, 문제지 원문을 사람이 검수한 수준으로 복원하는 것이다.

반드시 아래 순서로 처리한다.

1. PDF 전체 읽기
2. 문제 영역과 정답·해설 영역 분리
3. 반복 머리말, 페이지 번호, 워터마크, 사이트명 제거
4. 문제 경계 분리
5. 문제 유형 판정
6. 발문, 본문, 선지, 주어진 글, 요약문 구조화
7. 삽입/순서 유형의 `givenText` 분리
8. PDF 전체 밑줄 복원
9. 정답·해설 매칭
10. OCR 오류, 줄바꿈 오류, 띄어쓰기 오류, PDF 인코딩 오류 보정
11. JSON 초안 생성
12. 전체 오타, 띄어쓰기, 밑줄, 유형 후검수
13. 최종 검증
14. 최종 JSON 파일 제공

중간 단계 일부만 수행한 파일을 최종본이라고 말하지 않는다.

---

# 1. 기본 JSON 구조

최상위 구조는 반드시 아래 형식을 따른다.

```json
{
  "sourceName": "원본 파일명",
  "textbookName": "",
  "problems": []
}
```

`problems`에는 문제 객체를 PDF 원문 순서대로 넣는다.

`number`는 PDF LAB 내부 순서 번호다. PDF 원문 문제 번호가 215번이어도, JSON 안에서는 추출 순서대로 1부터 다시 부여한다.

---

# 2. 공통 필드 규칙

## 2.1 필수 필드

각 문제 객체는 아래 필드를 기본으로 가진다.

```json
{
  "number": 1,
  "passageLabel": "",
  "problemType": "",
  "isSubjective": false,
  "questionText": "",
  "bodyText": "",
  "summaryText": "",
  "givenText": "",
  "choices": [],
  "answerText": "",
  "explanationText": "",
  "rawText": ""
}
```

## 2.2 passageLabel

`passageLabel`은 지문 참조 라벨만 저장한다.

올바른 예:

- `17-3`
- `25-2`
- `T3-15`
- `T1-24~25`

잘못된 예:

- `[17-3]`
- `[T3-15]`
- `17-3 다음 글의 제목으로 가장 적절한 것은?`

`questionText`에는 원문 발문에 붙어 있는 `[17-3]` 같은 참조 표시를 포함해도 된다. 단, `passageLabel`에는 대괄호를 넣지 않는다.

## 2.3 정제 필드

아래 필드는 OCR 원문 복사가 아니라 PDF 원문을 기준으로 사람이 읽을 수 있게 보정한 AI 정제본이다.

- `questionText`
- `bodyText`
- `summaryText`
- `givenText`
- `choices.text`
- `answerText`
- `explanationText`

반드시 보정한다.

- 단어 중간 줄바꿈
- 하이픈·줄바꿈으로 갈라진 단어
- 잘못 붙은 단어와 잘못 떨어진 단어
- 한국어 발문 중간 줄바꿈으로 생긴 어색한 표현
- 선택지 번호와 선택지 텍스트 사이의 비정상 줄바꿈
- PDF 인코딩 이상 문자
- 명백한 OCR 오탈자

임의로 바꾸면 안 된다.

- 원문 고유명사
- 영국식 철자
- 낯설지만 원문에 실제로 있는 표현
- 의미가 달라질 수 있는 단어
- 저자명, 책 제목, 기관명

## 2.4 rawText

`rawText`는 원문 보존 필드다. 문제 경계 복원을 위한 라벨 정규화와 밑줄 보강은 가능하지만, 정답지·해설 영역이나 다른 문제 본문이 섞이면 안 된다.

## 2.5 출처 표기

지문 끝의 출처 표기 `[from ...]`, `[From ...]`, `[출처 ...]`는 정제 필드에 넣지 않는다.

아래 필드에서는 제거한다.

- `questionText`
- `bodyText`
- `summaryText`
- `givenText`
- `choices.text`
- `explanationText`

출처 표기를 보존해야 한다면 `rawText`에만 남긴다.

# 3. 선택지 구조

## 3.1 별도 선택지가 있는 문제

아래 유형은 별도 선택지 `choices`를 만든다.

- 순서
- 요약
- 선택어법
- 선택어휘
- 연결사
- 목적
- 심경
- 주장
- 함축의미
- 요지
- 주제
- 제목
- 내용
- 빈칸
- 별도 선택지가 있는 밑줄어휘
- 기타 중 별도 선택지가 있는 경우

객관식은 반드시 ①~⑤ 총 5개 선택지를 가진다.

```json
"choices": [
  { "marker": "①", "text": "" },
  { "marker": "②", "text": "" },
  { "marker": "③", "text": "" },
  { "marker": "④", "text": "" },
  { "marker": "⑤", "text": "" }
]
```

선택지 번호로 인정하는 것은 아래뿐이다.

- `①`, `②`, `③`, `④`, `⑤`
- 줄 시작의 `1`, `2`, `3`, `4`, `5`
- 줄 시작의 `1.`, `2.`, `3.`, `4.`, `5.`
- 줄 시작의 `1)`, `2)`, `3)`, `4)`, `5)`

연도, 문항 번호, 본문 속 숫자, 페이지 번호, `2011`, `2014`, `2020` 같은 숫자는 선택지 번호가 아니다.

## 3.2 embedded 유형

아래 유형은 본문 내부 ①~⑤ 표시가 선택지가 아니라 판단 대상이므로 `choices`를 만들지 않는다.

- 삽입
- 밑줄어법
- embedded 밑줄어휘
- 무관
- 지칭

이 유형들의 ①~⑤는 `bodyText` 안에 남긴다.

## 3.3 선택어법/선택어휘 AB·ABC 선택지

선택어법과 선택어휘는 선택지 텍스트가 AB 또는 ABC 조합일 수 있다.

예:

```json
{ "marker": "①", "text": "which - to use - are" }
{ "marker": "②", "text": "that - using - is" }
```

절대 `A`, `B`, `C`를 각각 독립 선택지로 만들지 않는다. 선택지는 항상 ①~⑤ 다섯 줄이다.

# 4. 허용 문제 유형

`problemType`은 아래 20개 중 하나만 사용한다.

- `삽입`
- `순서`
- `요약`
- `선택어법`
- `선택어휘`
- `연결사`
- `밑줄어법`
- `밑줄어휘`
- `무관`
- `지칭`
- `빈칸`
- `함축의미`
- `내용`
- `제목`
- `주제`
- `요지`
- `주장`
- `목적`
- `심경`
- `기타`

아래 명칭은 최종 `problemType`으로 쓰지 않는다.

- `내용일치`
- `내용불일치`
- `무관문`
- `어법`
- `어휘`
- `분위기`
- `심경변화`

변환 규칙:

- `내용일치`, `내용불일치` → `내용`
- `무관문` → `무관`
- `어법` → 문맥에 따라 `밑줄어법` 또는 `선택어법`
- `어휘` → 문맥에 따라 `밑줄어휘` 또는 `선택어휘`
- `분위기`, `심경변화` → `심경`

# 5. 문제 경계 인식

## 5.1 제거 대상

아래는 문제 본문에 넣지 않는다.

- `EBS연계 수능특강`
- `너른터 - 숫자 - nernter.com`
- 페이지 번호만 있는 줄
- 사이트명
- 워터마크
- 반복 머리말
- 반복 꼬리말
- 정답지 또는 해설 영역 표제

## 5.2 깨진 지문 라벨 복원

문제 시작점을 찾기 전에 대괄호 안 줄바꿈과 불필요한 공백을 복원한다.

- `[25-\n3]` → `[25-3]`
- `[29-\n1]` → `[29-1]`
- `[T3-\n15]` → `[T3-15]`
- `[T1-24~\n25]` → `[T1-24~25]`

## 5.3 문제 시작점

문제 시작점은 문항 번호만으로 판단하지 않는다. 다음 요소를 함께 본다.

- 새 한국어 발문
- `[17-3]`, `[T3-5]`, `[T1-24~25]` 같은 지문 라벨
- 이어지는 영어 본문
- 앞 문제 선택지 ⑤ 이후 새 발문
- 앞 문제 출처 표기 이후 새 발문

## 5.4 문제 종료점

한 문제는 다음 중 가장 먼저 등장하는 지점 직전에서 끝난다.

1. 다음 문제의 한국어 발문 시작점
2. 정답지 또는 해설 영역 시작점
3. 명확한 비문제 영역 시작점

다음 표제가 전체 추출 영역으로 등장하면 이후 텍스트는 문제 본문이나 `rawText`에 넣지 않는다.

- `(정답지)`
- `정답지`
- `정답`
- `해설`
- `Answers`
- `Answer Key`

# 6. 유형 판정 우선순위

문제 유형은 반드시 발문과 구조를 함께 보고 판정한다. 문항 번호나 `passageLabel`만으로 판단하지 않는다.

충돌이 생기면 아래 순서로 판단한다.

1. 삽입/순서 구조 여부 확인
2. 밑줄 표현 의미, 대체표현, 어법, 어휘 여부 확인
3. 선택지가 담화 연결사 조합인지 확인
4. 요약문 `(A)`, `(B)` 완성 여부 확인
5. 본문 내부 연결사 `(A)`, `(B)` 여부 확인
6. 빈칸 여부 확인
7. 내용 일치·질문 가능 여부 확인
8. 목적/주장/요지/주제/제목/심경 여부 확인
9. 그래도 맞지 않으면 `기타`

특별 우선 규칙:

- `밑줄 친 부분과 바꿔 쓸 수 없는 표현`은 `밑줄어휘`다.
- `밑줄 친 표현의 문맥상 의미를 영어로 설명`은 `함축의미`다.
- `(A), (B)에 들어갈 말`은 선택지가 담화 연결사 조합이면 `연결사`가 `요약`보다 우선한다.
- `(A), (B)에 들어갈 말`은 요약문 구조가 있고 선택지가 일반 어휘 조합이면 `요약`, 본문 내부 연결어 자리이거나 선택지가 담화 연결사 조합이면 `연결사`다.
- `답할 수 없는 질문`은 `내용`이다.
- `다섯 사람의 의견 중 적절하지 않은 것`은 `내용`이다.
- `다음 문장의 흐름상 가장 어색한 것은?`은 `무관`이다.
- `어조로 가장 적절한 것은`, `필자의 어조`는 `심경`이 아니라 `기타`다.

# 7. 유형별 판정 규칙

## 7.1 내용

다음 발문은 `내용`으로 분류한다.

- `다음 글의 내용과 일치하지 않는 것은?`
- `다음 글의 내용과 일치하는 것은?`
- `다음 글에 관한 내용으로 적절하지 않은 것은?`
- `다음 글에 관한 내용으로 적절한 것은?`
- `다음 글에 답할 수 없는 질문을 고르시오.`
- `다음 글에 답을 할 수 없는 질문을 고르시오.`
- `다섯 사람의 의견 중 적절하지 않은 것은?`
- `다섯 사람의 의견 중 적절한 것은?`
- 본문 이해를 바탕으로 선택지 진위를 판단하는 문제

## 7.2 밑줄어휘

다음 발문은 `밑줄어휘`로 분류한다.

- `다음 글의 밑줄 친 부분 중, 문맥상 낱말의 쓰임이 적절하지 않은 것은?`
- `다음 글의 밑줄 친 부분 중, 문맥상 낱말의 쓰임이 적절한 것은?`
- `밑줄 친 부분과 바꿔 쓸 수 없는 표현을 고르시오.`
- `밑줄 친 부분과 바꿔 쓸 수 있는 표현을 고르시오.`
- 밑줄 친 단어·구의 동의어, 반의어, 대체 표현, 어휘 적절성을 묻는 문제

혼합형이면 `problemType`은 `밑줄어휘`로 두고, 별도 선택지는 `choices`에 넣는다. 본문 내부 표현은 `bodyText`에 `① [[u:...]]`로 표시한다.

## 7.3 함축의미

다음 발문은 `함축의미`로 분류한다.

- `밑줄 친 표현이 의미하는 바로 가장 적절한 것은?`
- `밑줄 친 표현의 의미로 가장 적절한 것은?`
- `밑줄 친 표현의 문맥상 의미를 영어로 설명한 것으로 적절하지 않은 것은?`
- `밑줄 친 표현의 문맥상 의미를 영어로 설명한 것으로 적절한 것은?`
- 문맥상 특정 밑줄 표현의 의미, 함축, 비유적 의미, 설명을 묻는 문제

## 7.4 요약

다음 구조는 `요약`으로 분류한다.

- 발문이 `(A), (B)에 들어갈 말로 가장 적절한 것은?`
- 본문 뒤에 요약문 또는 summary sentence가 있음
- 요약문 안에 `(A)`, `(B)` 빈칸이 있음
- 선택지가 `(A)`와 `(B)`에 들어갈 말의 조합으로 제시됨
- 원문 전체를 요약한 문장 완성을 요구함

요약문 표지가 `[요약]`으로 명시될 수도 있고, 아무 표지 없이 본문과 한 줄 이상 띄어져 나올 수도 있다.

요약 처리:

- 원문 본문은 `bodyText`에 넣는다.
- 요약문은 `summaryText`에 넣는다.
- 선택지는 `choices`에 넣는다.
- 요약 유형에서 `summaryText`가 비어 있으면 오류다.
- 요약문 `(A)`, `(B)` 양옆에 실제 밑줄이 있으면 `[[u:___]](A)[[u:___]]`처럼 좌우 길이를 맞춘다.

요약과 연결사 구분:

- 선택지가 `However`, `Therefore`, `For example`, `In contrast`, `Moreover`, `In addition`, `On the other hand`, `As a result`, `Instead`, `Nevertheless`, `Similarly`, `Otherwise`, `Meanwhile`, `Consequently` 같은 담화 연결사 조합이면, 발문이 `(A), (B)에 들어갈 말로 가장 적절한 것은?`이어도 `요약`이 아니라 `연결사`
- 본문 뒤 별도 요약문 안의 `(A)`, `(B)`이고 선택지가 일반 명사·형용사·동사·구 조합이면 `요약`
- 본문 내부 담화 연결어 자리의 `(A)`, `(B)` → `연결사`

## 7.5 연결사

다음 구조는 `연결사`로 분류한다.

- 발문이 `(A), (B)에 들어갈 말로 가장 적절한 것은?`
- `(A)`, `(B)`가 요약문이 아니라 본문 내부 연결어 자리임
- 선택지가 `However`, `Therefore`, `For example`, `In contrast`, `Moreover` 등 담화 연결사 조합임
- 선택지 ①~⑤가 `In addition - However`, `For example - On the other hand`, `Nevertheless - As a result`처럼 연결사 두 개의 조합으로 되어 있음

중요:

- 같은 `(A), (B)에 들어갈 말` 발문이라도 선택지가 담화 연결사 조합이면 `요약`보다 `연결사`를 우선한다.
- 연결사 유형은 `summaryText`를 만들지 않는다.
- 본문 속 `(A)`, `(B)` 위치를 `bodyText`에 유지한다.

본문 내부 `(A)`, `(B)` 양옆에 실제 빈칸 밑줄이 있으면 `[[u:___]](A)[[u:___]]`처럼 좌우 길이를 맞춘다.

## 7.6 목적

다음 발문은 `목적`으로 분류한다.

- `다음 글의 목적으로 가장 적절한 것은?`
- 글의 목적, 의도, 쓰인 이유를 묻는 문제

## 7.7 심경

다음 발문은 `심경`으로 분류한다.

- `심경으로 가장 적절한 것은?`
- `심경 변화로 가장 적절한 것은?`
- `분위기로 가장 적절한 것은?`

주의:

- `어조로 가장 적절한 것은?`
- `필자의 어조로 가장 적절한 것은?`

위 발문은 `심경`이 아니라 `기타`로 둔다.

## 7.8 주장

다음 발문은 `주장`으로 분류한다.

- `필자가 주장하는 바로 가장 적절한 것은?`
- `글쓴이의 주장으로 가장 적절한 것은?`

## 7.9 요지

다음 발문은 `요지`로 분류한다.

- `다음 글의 요지로 가장 적절한 것은?`
- `필자가 말하고자 하는 바로 가장 적절한 것은?`
- 전체 글의 핵심 메시지를 묻는 문제

## 7.10 주제

다음 발문은 `주제`로 분류한다.

- `다음 글의 주제로 가장 적절한 것은?`
- `다음 글의 주제로 가장 알맞은 것은?`

## 7.11 제목

다음 발문은 `제목`으로 분류한다.

- `다음 글의 제목으로 가장 적절한 것은?`
- `다음 글의 제목으로 가장 알맞은 것은?`

## 7.12 빈칸

다음 구조는 `빈칸`으로 분류한다.

- 본문에 빈칸이 있음
- 발문이 `빈칸에 들어갈 말로 가장 적절한 것은?`
- 본문 내 한 자리 또는 여러 자리 빈칸 완성을 묻는 문제

빈칸은 PDF에서 실제 밑줄로 표시되어 있을 때만 `[[u:______]]`로 표시한다. 실제 밑줄이 없는 선택지 끝에 임의로 `______`를 붙이지 않는다.

## 7.13 순서

다음 구조는 `순서`로 분류한다.

- `주어진 글 다음에 이어질 글의 순서로 가장 적절한 것은?`
- 본문에 `(A)`, `(B)`, `(C)` 문단이 있음
- 선택지가 `(A)-(B)-(C)` 순서 조합임

순서 유형은 반드시 `givenText`를 분리한다.

- `(A)` 시작 전까지가 `givenText`
- `(A)`, `(B)`, `(C)` 이하가 `bodyText`
- `(A)`, `(B)`, `(C)` 표시는 `bodyText`에 보존
- `choices`는 ①~⑤ 다섯 개

## 7.14 삽입

다음 구조는 `삽입`으로 분류한다.

- `글의 흐름으로 보아, 주어진 문장이 들어가기에 가장 적절한 곳은?`
- 본문에 삽입 위치 표시 ①~⑤가 있음
- ①~⑤는 본문 내부 위치 표시이므로 `choices`를 만들지 않음

삽입 유형은 반드시 `givenText`를 분리한다.

- 본문 첫 한 문장이 `givenText`
- 나머지가 `bodyText`
- 첫 한 문장을 `givenText`와 `bodyText`에 중복하지 않음

## 7.15 무관

다음 발문은 `무관`으로 분류한다.

- `다음 글에서 전체 흐름과 관계 없는 문장은?`
- `글의 흐름과 무관한 문장은?`
- `다음 문장의 흐름상 가장 어색한 것은?`
- `다음 글의 흐름상 가장 어색한 문장은?`

무관 유형은 ①~⑤가 본문 내부 문장 표시이므로 `choices`를 만들지 않는다.

## 7.16 선택어법

다음 구조는 `선택어법`으로 분류한다.

- `(A)`, `(B)`, `(C)` 등에 두 어법 선택지가 제시됨
- 발문이 어법상 적절한 선택을 요구함
- 예: `(A) is / are`, `(B) which / what`

선택지는 ①~⑤ 다섯 개 조합으로 저장한다.

## 7.17 선택어휘

다음 구조는 `선택어휘`로 분류한다.

- `(A)`, `(B)`, `(C)` 등에 두 어휘 선택지가 제시됨
- 문맥상 적절한 낱말을 고르는 문제
- 예: `(A) increase / decrease`, `(B) include / exclude`

선택지는 ①~⑤ 다섯 개 조합으로 저장한다.

## 7.18 밑줄어법

다음 발문은 `밑줄어법`으로 분류한다.

- `다음 글의 밑줄 친 부분 중, 어법상 틀린 것은?`
- `다음 글의 밑줄 친 부분 중, 어법상 맞는 것은?`
- 제목이나 상단 유형명에 `문법`이 있고 본문 내부 ①~⑤ 밑줄 표현의 어법을 묻는 문제

embedded 유형이면 `choices`를 만들지 않는다.

## 7.19 지칭

다음 발문은 `지칭`으로 분류한다.

- `밑줄 친 he/she/it/they/this/that 등이 가리키는 대상이 나머지 넷과 다른 것은?`
- `밑줄 친 부분이 가리키는 대상이 나머지 넷과 다른 것은?`

지칭 유형은 보통 embedded 유형이므로 `choices`를 만들지 않는다.

## 7.20 기타

위 19개에 명확히 들어가지 않는 경우에만 `기타`로 둔다.

단, 아래는 `기타`로 두면 안 된다.

- `답할 수 없는 질문` → `내용`
- `다섯 사람의 의견 중 적절하지 않은 것` → `내용`
- `밑줄 친 부분과 바꿔 쓸 수 없는 표현` → `밑줄어휘`
- `밑줄 친 표현의 문맥상 의미 설명` → `함축의미`
- 요약문 `(A), (B)` 완성 + 일반 어휘 선택지 → `요약`
- `(A), (B)` 완성 + 담화 연결사 선택지 → `연결사`
- `다음 문장의 흐름상 가장 어색한 것은?` → `무관`

# 8. givenText 분리 규칙

## 8.1 삽입 유형

삽입 유형은 본문 첫 한 문장이 무조건 `givenText`다.

처리 규칙:

1. `givenText`에는 본문 첫 한 문장만 넣는다.
2. `bodyText`에는 첫 한 문장을 제외한 나머지 본문을 넣는다.
3. 첫 한 문장을 `givenText`와 `bodyText`에 중복하지 않는다.
4. 삽입 위치 표시 ①~⑤는 `bodyText`에 남긴다.
5. 삽입 유형은 `choices`를 만들지 않는다.
6. 삽입 유형에서 `givenText`가 빈 문자열이면 오류다.

## 8.2 순서 유형

순서 유형은 본문에서 `(A)`가 시작하기 전까지가 무조건 `givenText`다.

처리 규칙:

1. `givenText`에는 `(A)` 시작 전까지의 주어진 글을 넣는다.
2. `bodyText`에는 `(A)`, `(B)`, `(C)` 이하의 문단들을 넣는다.
3. 주어진 글을 `givenText`와 `bodyText`에 중복하지 않는다.
4. `(A)`, `(B)`, `(C)` 표시는 `bodyText`에 보존한다.
5. 순서 유형은 `choices`를 만든다.
6. 순서 유형에서 `givenText`가 빈 문자열이면 오류다.

---

# 9. 요약문 분리 규칙

요약 유형은 `bodyText`와 `summaryText` 분리가 가장 중요하다.

## 9.1 요약문 표지가 있는 경우

`[요약]`, `요약`, `Summary` 같은 표지가 있으면 그 뒤 문장을 `summaryText`로 본다.

## 9.2 요약문 표지가 없는 경우

요약문 표지가 없어도 아래 조건을 만족하면 요약문으로 분리한다.

- 본문과 한 줄 이상 띄어져 있음
- 문장 안에 `(A)`, `(B)`가 있음
- 선택지가 두 단어 또는 두 표현의 조합임
- 발문이 `(A), (B)에 들어갈 말로 가장 적절한 것은?` 형태임

## 9.3 요약문 밑줄

요약문 안의 `(A)`, `(B)` 양옆에 실제 밑줄이 있으면 좌우 길이를 맞춘다.

올바른 예:

- `People usually blame themselves for the lack of [[u:___]](A)[[u:___]], but the true issue is the absence of [[u:___]](B)[[u:___]].`

잘못된 예:

- `____(A)__`
- `[[u:___(A)________]]`
- `[[u:]](A)[[u:]]`

---

# 10. 밑줄 복원 규칙

PDF에서 실제 밑줄이 보이는 모든 부분은 위치와 필드를 가리지 않고 `[[u:...]]`로 감싼다.

대상 필드:

- `questionText`
- `bodyText`
- `givenText`
- `summaryText`
- `choices.text`
- 필요 시 `rawText`

## 10.1 실제 밑줄만 표시

실제 PDF에 밑줄이 보이는 경우에만 `[[u:...]]`를 사용한다.

금지:

- 밑줄 없는 선택지 끝에 임의로 `______` 추가
- 양쪽 정렬 때문에 넓어진 빈칸을 밑줄로 착각
- 긴 공백을 무조건 밑줄로 변환
- 부정어가 중요해 보인다는 이유만으로 밑줄 추가

## 10.2 발문 밑줄

문제 발문에서 실제로 밑줄이 그어진 부정어·핵심어는 반드시 `questionText`에 표시한다.

예:

- `적절하지 [[u:않은]] 것은?`
- `일치하지 [[u:않는]] 것은?`
- `어법상 [[u:틀린]] 것은?`
- `답할 수 [[u:없는]] 질문은?`
- `바꿔 쓸 수 [[u:없는]] 표현은?`

## 10.3 본문 밑줄

본문 속 ①~⑤가 밑줄 판단 대상이면 번호는 밑줄 밖에 두고 표현만 감싼다.

올바른 예:

- `① [[u:use]]`
- `② [[u:reach]]`

잘못된 예:

- `[[u:① use]]`
- `① [[u:]]`

## 10.4 선지 밑줄

선택지 텍스트 자체에 실제 밑줄이 있으면 `choices.text`에 표시한다.

## 10.5 빈칸 밑줄

PDF에서 빈칸이 밑줄로 표시되어 있으면 `[[u:______]]`로 표시한다.

빈칸 안에 `(A)`, `(B)` 표시가 있으면 `(A)`, `(B)` 자체는 밑줄 밖에 둔다.

올바른 예:

- `[[u:______]]`
- `[[u:___]](A)[[u:___]]`
- `[[u:___]](B)[[u:___]]`

잘못된 예:

- `[[u:]]`
- `[[u:(A)]]`
- `[[u:____(A)____]]`

## 10.6 밑줄 누락 금지 조건

다음 조건 중 하나라도 해당하면 해당 문제 안에 실제 밑줄이 있는지 반드시 확인한다.

- 발문에 `밑줄 친`이 있음
- 발문에 `밑줄 친 부분`, `밑줄 친 표현`, `밑줄 친 낱말`이 있음
- 발문에 `바꿔 쓸 수 없는 표현`이 있음
- 발문에 `어법상 틀린`이 있음
- 발문에 `문맥상 적절하지 않은`이 있음
- 발문에 `지칭하는 대상`이 있음
- `problemType`이 `밑줄어법`, `밑줄어휘`, `지칭`, `함축의미`임

빈 밑줄 태그 `[[u:]]`는 절대 만들지 않는다.

# 11. 정답·해설 영역 분리 및 매칭

PDF에 정답지 또는 해설 영역이 있으면 폐기하지 않는다. 문제 영역과 분리한 뒤 각 문제 객체의 `answerText`, `explanationText`에 매칭한다.

## 11.1 영역 분리

정답·해설 영역의 텍스트는 아래 필드에 넣지 않는다.

- `bodyText`
- `rawText`
- `choices.text`
- `givenText`
- `summaryText`

## 11.2 항목 인식

다음 패턴을 하나의 해설 항목 시작점으로 본다.

- `1 번 - ③`
- `1번-③`
- `1. ③`
- `1) ③`
- `1 ③`
- `001 번 - ③`
- `Answer 1: ③`

각 항목은 다음 정답 번호가 나오기 전까지를 해당 문제의 해설로 본다.

## 11.3 매칭 기준

정답·해설은 문제 순서 번호를 우선한다. `passageLabel`만으로 매칭하지 않는다.

## 11.4 answerText

객관식 `answerText`에는 정답 표시만 넣는다.

올바른 예:

- `①`
- `②`
- `③`
- `④`
- `⑤`

잘못된 예:

- `A`
- `B`
- `C`
- `Co`
- `정답은 ④입니다.`
- `④ 글의 내용과 일치한다.`

해설 첫 글자나 본문 속 대문자를 정답으로 추출하지 않는다.

## 11.5 explanationText

`explanationText`에는 정답 번호와 정답 표시를 제외한 해당 번호 해설만 넣는다. 다음 번호 해설이 섞이면 오류다.

원본 답지에 해설 없이 정답만 있으면 `explanationText`는 빈 문자열 `""`로 둔다. 해설을 임의로 만들어내지 않는다.

# 12. JSON 초안 후검수

JSON 초안을 만든 뒤 전체를 다시 훑어 오타, 띄어쓰기, 밑줄, 유형 오류를 수정한다.

반드시 확인한다.

1. JSON 파싱 가능 여부
2. 문제 수와 정답 매칭 수 일치 여부
3. `passageLabel`에 대괄호가 남았는지 여부
4. 지문 출처 `[from ...]`가 정제 필드에 남았는지 여부
5. 특수 발문 유형이 `기타`로 빠졌는지 여부
6. `(A), (B)에 들어갈 말로 가장 적절한 것은?` 요약형이 `기타`로 빠졌는지 여부
7. 삽입 유형의 `givenText` 누락 여부
8. 순서 유형의 `givenText` 누락 여부
9. 요약 유형의 `summaryText` 누락 여부
10. `[[u:]]` 빈 태그 존재 여부
11. `[[u:①`처럼 번호가 밑줄 안에 들어간 경우
12. 발문에 `밑줄 친`이 있는데 `[[u:`가 없는 문제
13. 발문 밑줄 부정어가 `questionText`에 반영되지 않은 문제
14. 실제 밑줄이 없는 곳에 `[[u:...]]`가 들어간 문제
15. 빈칸 밑줄 누락
16. embedded 유형인데 `choices`가 생긴 문제
17. 별도 선택지가 있는데 `choices`가 누락된 문제
18. 객관식 선택지 수가 5개가 아닌 문제
19. `answerText`에 해설 문장이 섞인 문제
20. `explanationText`에 다음 번호 해설이 섞인 문제
21. 정제 필드에 명백한 OCR·띄어쓰기·인코딩 오류가 남은 문제

---

# 13. 최종 검증 체크리스트

아래 오류가 하나라도 있으면 최종본으로 출력하지 말고 다시 수정한다.

1. JSON 파싱 불가
2. 정답·해설 영역이 문제 필드에 섞임
3. 다른 문제 발문이 `bodyText` 또는 `rawText`에 섞임
4. `passageLabel`에 대괄호가 있음
5. 지문 출처 `[from ...]`가 정제 필드에 남아 있음
6. 삽입 유형인데 `givenText`가 비어 있음
7. 순서 유형인데 `givenText`가 비어 있음
8. 순서 유형인데 `(A)` 시작 전까지의 글이 `givenText`가 아님
9. 요약 유형인데 `summaryText`가 비어 있음
10. embedded 유형에 `choices`가 있음
11. 별도 선택지가 있는 유형인데 `choices`가 누락됨
12. 객관식 선택지 수가 5개가 아님
13. 발문에 `밑줄 친`이 있는데 해당 문제에 `[[u:`가 없음
14. 발문 자체에 실제 밑줄이 있는데 `questionText`에 `[[u:...]]`가 없음
15. 밑줄 관련 유형인데 실제 밑줄이 누락됨
16. 실제 밑줄이 없는 곳에 `[[u:...]]`가 들어감
17. `[[u:]]` 빈 밑줄 태그가 있음
18. 번호가 불필요하게 밑줄 안에 들어감
19. 빈칸 밑줄이 누락됨
20. 선택지 밑줄이 누락됨
21. 정제 필드에 명백한 OCR·띄어쓰기·인코딩 오류가 남음
22. 정답 매칭 수와 문제 수가 불일치
23. `answerText`에 해설 문장이 섞임
24. `explanationText`에 다음 번호 해설이 섞임
25. 아래 유형이 `기타`로 분류됨:
   - `답할 수 없는 질문`
   - `다섯 사람의 의견 중 적절하지 않은 것`
   - `밑줄 친 부분과 바꿔 쓸 수 없는 표현`
   - `밑줄 친 표현의 문맥상 의미 설명`
   - 요약문 `(A), (B)` 완성 + 일반 어휘 선택지
   - `(A), (B)` 완성 + 담화 연결사 선택지
   - `다음 문장의 흐름상 가장 어색한 것은?`

# 14. 최종 응답 통계

최종 응답에는 JSON 파일 링크와 함께 다음을 간단히 포함한다.

- 총 문제 수
- 정답 매칭 수
- 유형 후검수 완료 여부
- 삽입 유형 수와 `givenText` 누락 수
- 순서 유형 수와 `givenText` 누락 수
- 요약 유형 수
- 요약 `summaryText` 누락 수
- `기타`로 남은 문제 수
- `기타` 문제 번호와 발문 목록
- 전체 `[[u:` 개수
- `questionText` 밑줄 개수
- `bodyText` 밑줄 개수
- `summaryText` 밑줄 개수
- `choices.text` 밑줄 개수
- 빈 `[[u:]]` 개수
- 오타·띄어쓰기 후검수 완료 여부

JSON은 채팅 본문에 길게 붙여넣지 말고 다운로드 가능한 `.json` 파일로 제공한다.
