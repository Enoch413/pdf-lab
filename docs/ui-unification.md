# PDF LAB 작업 화면 통일 — 2026-10-20

상태: 사용자 승인에 따라 남은 검증 후 `main`의 GitHub Pages로 배포하는 변경이다. 배포 대상은 웹 UI·공통 스크립트·포터블 사본이며, 운영 문항·학생·출제 이력과 Firebase 규칙은 변경하지 않는다.

## 적용 범위

- 시작 화면, 반별 출제, 파이널테스트, 문제 라이브러리, 일반 출제, 쏠북메이커에 동일한 헤더와 5개 메뉴를 적용했다.
- `app/workspace_shell.js`가 메뉴·현재 위치·본문 바로가기를 생성한다. 각 HTML의 `data-lab-root`를 기준으로 주소를 만들므로 GitHub Pages 하위 경로에서도 동작한다.
- `app/workspace_shell.css`가 기존 녹색·크림색 브랜드의 화면용 공통 규칙을 관리한다. 최대 폭 1520px, 바깥 여백 24px, 열 간격 24px, 사이드바 390px, 일반 입력란·주요 버튼 최소 높이 44px, 카드 모서리 16px가 기준이다.
- 1100px 이하에서 한 열로 전환하고, 760px 이하에서는 바깥 여백 16px와 가로 스크롤 메뉴를 사용한다. 현재 메뉴가 보이도록 초기 위치를 맞춘다.
- 반별 출제·파이널테스트의 출력 설정을 결과 검토 다음으로 이동했다. 저장 작업과 CHECK 연동은 접어서 필요한 때 펼치도록 했다. 기존 컨트롤 ID와 이벤트 연결은 유지했다.
- 일반 출제의 빈 화면 안내와 숨김 상태를 정리했다. 다운로드 링크가 저장하지 않은 작업의 화면 이탈 경고를 띄우던 문제를 공통 이동 보호 코드에서 수정했다.

## 출력과 포터블 유지

화면 스타일은 `@media screen` 및 `.pdflab-workspace` 아래에 둔다. 시험지의 글꼴·치수·단 구성·PDF 생성 함수는 변경하지 않는다. 공통 UI의 `--ui-*` 변수는 기존 출력 변수와 분리한다.

포터블의 `dist/solbook_question_maker_portable/app/workspace_shell.js`와 `.css`는 `app/` 원본과 바이트 단위로 같아야 한다. `tests/workspace_shell.test.cjs`가 두 복사본과 메뉴 경로·현재 위치·기존 이벤트 대상 ID를 검사한다. 기존 폰트·로고·vendor 파일은 보존했다.

## 검증 결과

- `node tests/run_checks.cjs`: JavaScript 12개 검사 묶음, Python 5개 검사 통과.
- `PDFLAB_JSON_CHECK_DIR`에 제공된 JSON 폴더를 지정해 23개 파일·2,307문항의 일반형/차수형 관련 회귀 검사 통과.
- 브라우저에서 일반 JSON 2개·21문항 동시 가져오기 성공. canonical JSON을 다중 업로드하면 기존 안내대로 거부하고 작업을 유지하는 것도 확인했다. 클라우드 저장은 실행하지 않았다.
- 쏠북메이커 실제 PDF 다운로드 4쪽, ZIP 다운로드 안의 1~3차 PDF 각 2쪽 확인. 수정 전 운영 검증 출력과 텍스트·페이지 수·1200px 렌더링 이미지가 모두 동일했다.
- 일반 출제에서 지원 번호 형식의 합성 PDF 6문항 추출 및 이미지 미리보기 확인. 지원하지 않는 번호 형식은 기존 오류 안내를 표시했다.
- 모든 화면을 데스크톱 1280px, 모바일 390px 폭에서 확인했고, 반별 출제는 768px에서도 확인했다. 확인한 빈 화면에서 문서 전체의 가로 넘침은 없었다. 데스크톱 헤더는 80px, 일반 입력란은 44px로 일치했다.
- 기존 HTML의 컨트롤 ID 누락·중복 없음. 반별 출제 797개, 파이널테스트 468개, 쏠북메이커 137개 기존 함수가 그대로이며, 일반 출제는 빈 화면 문구를 바꾼 `renderPreview`만 다르다.
- 로컬 서버 요청에서 실제 자산 404는 없었다. 시작 화면의 누락 favicon 요청은 빈 아이콘 선언으로 없앴다.
- Impeccable 정적 검사는 공통 CSS에 새 문제를 보고하지 않았다. 연결된 기존 CSS의 폰트 취향·출력 카드 장식 및 화면용 덮어쓰기를 반영하지 못한 경고는 임의의 출력 디자인 변경 근거로 삼지 않았다.

## 배포 전 추가 검증

- 일반 출제에서 합성 PDF 6문항을 다시 추출하고 `general-input_layout.html` 실제 다운로드를 확인했다. 저장 파일은 2개 시험지, 유효한 내장 PNG 6개, 응답하는 로고 URL, 실행 스크립트 없음으로 검증했다. 다운로드 때 화면 이탈 확인창이 뜨지 않았다.
- 사용자가 로컬 화면에 기존 관리자 계정으로 로그인한 뒤 반 4개·선택 반 학생 6명의 연결과 공용 라이브러리 읽기를 확인했다. 브라우저 warn/error는 없었다. 테스트 문항·학생·CHECK 세트·출제 이력의 운영 저장은 실행하지 않았다.
- 미저장 작업의 이동·초기화 취소 및 문항 보존은 공통 코드의 자동 검사로 검증했다. 브라우저 자동화 도구는 자바스크립트 확인창 처리에서 연결이 멈추는 제한이 있어 별도로 구분한다.
- 저장 HTML의 `file:` 직접 열기는 검증 브라우저의 프로토콜 정책이 허용하지 않아 파일 파싱·이미지 검증으로 확인했다. 실제 모바일 기기·물리 프린터 출력은 검증하지 않았다.
